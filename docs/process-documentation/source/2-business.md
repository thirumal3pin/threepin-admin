# Document 2 · Business guide — how to use it, and why at that point

Every feature exists to remove one of four business risks: **a lead nobody answers, a seller nobody lists, a property nobody can find the facts for, and money nobody tracks.** This guide follows the business day and the property lifecycle, and for each feature says when to use it, how, and what it saves.

## The property lifecycle, stage by stage

| Stage | Use this | How | Why at this point |
| --- | --- | --- | --- |
| 1 · Find the owner | CRM (TailorTalk chats, Add Lead) | Owner enquiries arrive from WhatsApp, Instagram, the website, or are typed in | No owner is lost: the AI re-tags confident sellers, and a phone number is never entered twice |
| 2 · Card for the property | Shoot & Media → Sellers / Board | A card appears for every seller automatically; **Create now** for any still waiting | "A seller who never gets a card is revenue that silently evaporates" — the Sellers badge shows who is still waiting |
| 3 · Onboard | Card panel → Listing type, asking price, location; Edit details | Record Normal / Exclusive / Collab and the terms discussed | One place for the agreed terms, shown on the card and in the property's Shoot & Media block (the type is recorded; it gates nothing yet) |
| 4 · Details & documents | Card → Listing & documents; brochure panel | Tick each paper Have it / Applied for / Missing / Not needed; fill title, photos folder, description, internal notes | The paper chase is visible per property ("n of m in hand"); nothing waits on it, so marketing is not blocked |
| 5 · Brochure v1 | Brochure panel → Generate | Send the request; in ~30 min the PDF is emailed and the card links itself | A brochure can go out before the shoot, from the photos already available |
| 6 · Map to inventory | Card → Map to a property | Pick the property code by hand | Ties the card, the seller lead, Posting and the dashboard to one code — by hand so a chat can never mis-link it |
| 7 · Plan the shoot | Card → Getting there, Book the shoot, Owner told | Address, contact, access notes; date, time, shooter; tick Owner told | The shooter arrives with everything; a clash within 2 h is flagged; "not ready to send" warns before a wasted trip. With the Settings switch on, the booking also lands on the team calendar with the shooter invited (off by default, because it sends real Google invitations) |
| 8 · Shoot day | Shoots run sheet | Next up with **Call**, **Directions**, **✓ Done** | One phone screen for the whole day — no calls back to the office |
| 9 · After the shoot | **Shoot done** dialog | Tick what was captured, paste the raw photos Drive link, add notes | Easy to update the shoot details right after completion; the card moves on by itself |
| 10 · Plan posts and edits | Card → Shoot for; Plan the edit; Posting → Paste week plan | Choose outlets and V/O per outlet; assign the editor and deliver-by date; paste the owner's week plan | Every outlet's cut has an owner and a deadline; the plan text becomes scheduled rows |
| 11 · Edit | Editor view | Plan → **Start editing** → **Edit done** per outlet; paste the **final video link** if you want it on the card | Each editor sees only their queue, late items first; time per edit is measured; the finished file can be found from the card |
| 12 · Voice-over | **Ask for V/O** on the rough cut → **V/O made ✓** | The request lands in the voice-over person's CRM Daily task | No V/O is forgotten; it is asked for only when there is a cut to voice |
| 13 · Brochure v2 | Brochure panel → Redo brochure | Regenerate with the shoot photos | When a shoot is completed after the brochure was made, the card says so ("it does not have these photos") until a new version is made or **Not needed** is pressed |
| 14 · Media ready | Automatic | The card moves itself once photos, edits, V/O and brochure are done | Nobody has to remember to move it; the column is always true |
| 15 · Post | Posting → schedule → **Confirm posted** + URL | Schedule each channel; when it goes out, confirm and paste the link | Nothing is "posted" by the clock alone; every live post has its URL saved against the property and is listed in the property's **Shoot & Media and posts** block |
| 16 · Market | Property dashboard → Matching Buyers; CRM → Properties for this buyer | Call the strongest matches first | The same engine everywhere, so every agent sees the same ranking |
| 17 · Site visits | CRM lead → Site visit | Pick day, time and agents; save | Easily co-ordinate site visits: agents get a private calendar invitation with the client, seller and address; declines flag at once |
| 18 · Negotiate and close | CRM stages; Finance deal | Move to Negotiating / Won; open a Finance deal, record the token, invoice each side | Brokerage, GST and receipts are tracked per property and side |
| 19 · Sold | Property dashboard → Mark Sold Out; board → Sold / Rented | One tick takes it out of every buyer's matches | No agent pitches a sold property again |

## A day for each role

### Sales agent

| When | Do this | Why |
| --- | --- | --- |
| Morning | Read the **09:00 digest** email; open **Daily task** | One list of today's visits, calls due and teammates' asks |
| All day | Work the **Follow-ups → Needs a person** queue, red first | Critical items (promise overdue, WhatsApp window closing) are worth the most |
| After every call | Answer **"What happened on the call?"** and set the next follow-up | Reminders: the next contact is never left to memory |
| On a buyer | **Properties for this buyer**, then ＋ Link what you shared | Matching and a record of what was already sent |
| Before a visit | Schedule the **site visit** with the agents going | Everyone gets the invitation and the seller's number |
| After a visit | **They visited** → "How did the visit go?" | Moves the lead and captures feedback while it is fresh |
| On a lost lead | Pick the **reason** | Loss reasons feed the evening summary and analytics |

### Owner / Swami

| When | Do this | Why |
| --- | --- | --- |
| Weekly | **Paste week plan** in Posting | The plan becomes dated rows for every channel |
| On a card | Decide outlets and **V/O yes / separately** in Shoot for | Editors and the V/O person get their work from it |
| Evening | Read the **21:30 summary** | Escalations, the day's movement and why leads were lost |
| Any time | Board → **Needs attention** sort | Late cards (amber, red) rise to the top |
| On a property | Property dashboard → **Shoot & Media and posts** | Where the property stands in marketing — card, column, shoot, every post and link — without leaving the dashboard |

### Shooter

Open **Shoots** on the phone (tick "this is me" once). Work **Next up**: Call, Directions, ✓ Done. In **Shoot done**, tick what was captured and paste the Drive folder — that is the hand-off to the editor.

### Editor

Open the **Editor** view (it opens on your own work). Late cards come first. **Start editing** when you begin, **Edit done** when finished (then **+ Final video link** if you want the finished file findable from the card — optional), and **Ask for V/O** once a rough cut exists.

### Inventory maintainer

Type facts in the **Inventory sheet**; press **Sync from sheet** if the Mac is off. Work **Changes to apply → Pending**: copy each change into the sheet, then tick it. Clear **Missing data** before client calls; resolve **Duplicates** by hand.

### Accounts / owner (Finance)

Use **Record** for every money event the day it happens (photograph the receipt). Import the **bank statement** monthly, reconcile, then **Run month-end**. Hand the CA the exports from **Books**.

## Why it is built this way

| Design choice | Business reason |
| --- | --- |
| Board mapping by hand only | A chat that mentions a code must never attach the wrong property to a seller |
| One property, one card | No two cards compete for the same shoot or brochure |
| Sheet is the typing surface, no automatic write-back | One place to type facts; edits made in the dashboard are listed for reconciliation, never lost |
| AI never marks Won and never overrides a person | Sales outcomes and team decisions stay human |
| Site-visit invitations only to team members, marked private | Client and seller phone numbers never leave the team |
| Documents never block posting | Marketing starts while papers are chased |
| Confirm posted needs a person | The URL record is always real |
| Append-only change log and ledger | Every edit and every rupee can be traced and recovered |
| Every admin option in Settings → Configurations | People and rules change without a code change |
| A save waits for the server's list ("Still connecting") | A phone that opens on its old saved copy can never write that copy over a colleague's newer work |
| Leads are read from packed view documents | Opening the CRM costs about 39 reads instead of 760, so the daily database bill stays flat as the lead count grows; the leads themselves stay the source of truth |
| Shoot invitations are off until switched on | A calendar invitation is a real email to a real person; the switch is turned on deliberately in Settings |
