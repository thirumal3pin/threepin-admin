The operating model · 3 PIN Autopilot

Three layers, each built on something that exists

3 · CHANNEL LAYER

Every channel writes to the same lead, card and facts

WhatsApp (TailorTalk, Flows, channels) · Instagram · an AI voice number in Tamil and English · the website and “Ask 3 PIN” · portal feeds

2 · AGENT LAYER · EÅSY BY 3 PIN

Supervised specialists, one coordinator, one approval queue

Sourcing, seller intake, media, outreach, follow-up, transaction, finance — Eåsy starts work before being asked; the owner clears approvals from the phone

1 · FACT LAYER

A nightly fact store, a Chennai price desk, a demand map

One compressed document per topic; every AI reads facts, never raw collections; exposed to Claude and ChatGPT through an MCP server

Rules that never change

  • A person approves Won, listings going public, agreements, prices and first contact with a new person
  • Every AI action is logged and undoable
  • Nothing reads customer data for a purpose it was not collected for
  • AI-made visuals are labelled

Seeds already built: the AI queue, suggestions and 7-day undo, the finance snapshot, the match engine, multi-tenancy.

Read the layers bottom-up: facts first, because every agent, report and score needs them and reading raw collections would blow the quota; then the agent layer, which is Eåsy; then the channels. Building channels before facts is the first way this plan fails — there would be nothing to say. The rules on the right are the owner's guardrails and never move.
